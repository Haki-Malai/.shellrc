# Reporting

Read when preparing an answer or handoff.

- Lead with the result and cite the supporting command output summary or file path with relevant lines. Separate observed facts from inference; say what remains unknown and how to verify it.
- For changes, explain what changed, why, and the relevant validation result. Report test failures and missing browser/live checks without implying that static inspection proves runtime behavior.
- If blocked, state what you tried, what happened, and what is needed next. Complete unaffected authorized work first.
- End substantive answers with `Confidence: N/10`. Use `10/10` only when the requested outcome is directly confirmed; otherwise briefly name the missing evidence or remaining risk. Do not give a whole-task score based only on one verified substep.
- Exact-output requests take precedence over the confidence footer and explanatory prose. When asked to identify key files, output only filenames on one line, comma-separated with no spaces; wildcards are allowed.
